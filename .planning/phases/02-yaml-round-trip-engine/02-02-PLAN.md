<objective>
Turn the single-file loader into a whole-tree engine: walk from `configuration.yaml` through
every `!include` and `!include_dir_*` tag using Home Assistant's own resolution rules, load each
resolved target as its own editable file node, and emit the include graph as a byproduct of that
walk (YAML-03, D-04, D-05).

Purpose: later phases edit inside any included file, so every reachable file has to arrive as a
first-class editable node with its own text and span index, and the graph is what tells the
optimizer and the apply stage which files are in play. The resolution rules are not ours to
invent - they are pinned verbatim from HA's `annotatedyaml` loader in RESEARCH.md, including the
recursive `os.walk` that corrected the original D-05 wording.

Output: `src/haco/configtree/{includes,graph,tree}.py`, the include error family in
`src/haco/errors.py`, `tests/test_configtree_includes.py`, `tests/test_configtree_graph.py`, and
the cycle / missing / escape negative fixtures.
</objective>

## Path conventions (fixed here, consumed by 02-03 and 02-04)

- `ConfigTree.root` and `FileNode.path` are absolute, resolved paths.
- `ConfigTree.files` is keyed by the path **relative to root**; `FileNode.rel` holds the same value.
- `IncludeEdge.parent` and `IncludeEdge.child` are relative to root, so graph assertions read cleanly and are portable.
- `Span.file` stays whatever `load_file` was handed - the absolute path - because the writer works from `FileNode.path`.
- `ConfigTree.node(p)` accepts either an absolute path or a root-relative one and returns the `FileNode`.
